# 中国个人账单获取与自动化核验（2026-11-02）

核验范围：支付宝、微信支付、招商银行、宁波银行的中国内地个人账户。只读取公开资料，没有登录账户、安装支付工具或获取任何凭证。以下“未找到”表示本次公开文档核验的结果，不等于断言银行不存在任何定向合作接口。

## 可直接采用的结论

- 微信的交易列表通常不会直接写“导出”。**腾讯当前官方文档仍确认下一步是“常见问题 → 下载账单”**，见下方路径。不能因为列表没有“Export”就认定不能导出。
- 支付宝和微信现在均有官方 AI 支付能力；这些能力用于购买、支付、绑定支付工具和返回本次订单结果。**不能据此接入一个普通用户过去所有商户、转账、红包和银行卡消费的完整流水。**
- 招商银行有官方消费者助手“小招”，可办理流水打印并发送邮箱；宁波银行官方资料确认 App 存在“打印交易流水”。目前可落地的入账链路仍是：用户在官方 App 发起导出 → 本地接收文件 → 有密码时本地解密 → 自动解析、去重、入账。
- 不应承诺“保存一次解压码，以后所有新账单永久免输入”。没有查到这些机构对跨导出任务复用同一密码的官方保证。保存已知密码只能作为本地解密候选；新文件匹配失败时应保留文件并显示“待解锁”。

## 微信：补齐真正缺少的入口

腾讯微信支付《订单退款常见问题》，页面更新时间 **2026-08-05**，在指导用户核对退款时明确给出：

`微信 → 我 → 服务 → 钱包 → 右上角账单 → 右上角常见问题 → 下载账单 → 用做证明材料 → 选择对应时间导出`

来源：[微信支付官方常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4013071200)。该页虽在商户文档中心，但这段说明明确描述消费者自己的微信操作路径。

对英文界面可按含义查找 `Me → Pay and Services/Services → Wallet → Transactions/Bills → FAQ → Download Bill`。**这些英文名称是导航翻译提示，腾讯上面的中文文档没有保证各版本使用完全相同的英文文案。** 若用户正在看的“交易明细”是零钱明细而非全部微信支付账单，应回到钱包找全账单入口。

用于导入时，在下载页**若有**“用于个人对账”则选择该用途，并以实际收到的 CSV/XLSX 为准。上面这一份当前官方网页只确认“用做证明材料”分支，不能用它证明个人对账分支的当前文件格式或日期上限。证明材料可能包含需要额外核验或不便结构化解析的文件，不能静默把它等同于 CSV 导出。

若没有“常见问题/FAQ”或“下载账单”：钱包内的 `消费者保护 → 帮助中心` 也由同一份腾讯文档确认存在。可以在官方帮助中查询“下载微信支付账单、用于个人对账”。这是稳妥的官方求助入口；**没有核验到一个可保证绕过版本差异、直接打开下载表单的公开深链接**。腾讯客服官网列有微信支付/财付通客服专线及官方客服入口：[腾讯客服](https://kf.qq.com/)（检索于 2026-11-02）。

本次没有从可访问的腾讯消费者原始资料核实：个人对账单次当前最多 3 个月还是 1 年、可以追溯多少年前、固定送达时限、是否所有账户都通过邮箱、解压码具体通知位置、每次申请是否生成新密码。网上教程对这些细节互相矛盾，不能把任一数字写成当前所有版本的事实。应以下载页的日期选择器和该次成功通知为准；若时间跨度受限，再按该页允许范围分段导出，全年覆盖不能只看文件名。

## 支付宝：完整交易记录与余额流水要区分

官方帮助确认：手机 `我的 → 账单` 可查看、筛选交易；电脑登录支付宝后 `首页 → 交易记录` 可查看交易记录。[支付宝：消费记录如何查询](https://cschannel.alipay.com/mobile/helpDetail.htm?help_id=201602030903)（未显示更新日期，2026-11-02 检索）。

官方另有**余额**收支明细下载：电脑登录支付宝，点击账户余额区域的“查看”，选择日期后“下载查询结果”；文件可编辑。该官方页面还说手机暂不能下载同类余额明细，但能开具余额证明。[支付宝：如何下载支付宝余额收支明细](https://cschannel.alipay.com/mobile/helpDetail.htm?help_id=201603346502)。这不应被描述为所有支付渠道的完整个人账单。

余额证明的官方手机路径是 `我的 → 总资产 → 资产证明 → 余额资产和流水证明 → 流水证明`，支持输入邮箱并验证身份。该产品的每次 1000 条限制只适用于这里的**余额收支明细证明**，不应移植成全量交易账单的限制。[支付宝：如何开具支付宝余额收支明细证明](https://cschannel.alipay.com/mobile/helpDetail.htm?help_id=201602096970)。

常见的 App 全账单路径是 `我的 → 账单 → … → 开具交易流水证明 → 用于个人对账`。但是，本次能访问到的支付宝消费者原始页面没有完整呈现这条当前表单；上述余额帮助链接到的全账单说明需要动态加载，匿名读取未得到内容。因此：**这条路径不能标成已实机验证，也不能把“申请记录查看解压码”、固定最多一年、每次密码规律写成已获支付宝官方确认。** 用户已在桌面的明文 CSV 可直接本地解析，GB18030/GBK 编码兼容应由文件本身验证，无须再次申请邮箱压缩包。

## 官方 Agent、MCP、API、CLI 的实际边界

| 机构 | 已确认的官方能力 | 本次未确认的能力 |
| --- | --- | --- |
| 支付宝 | Agent Pay、官方支付 CLI/Skills；消费者在官方页面核验并绑定后，Agent 可参与付款。 | 任意普通消费者账户的全部历史流水导出 API/MCP；支付授权不等于历史账单读取授权。 |
| 微信支付 | AI 支付插件/工具、AI 专属卡、传统订单加 x402 支付；商户账单 API。 | 普通消费者全部历史微信支付流水读取 API/MCP/CLI。 |
| 招商银行 | App 内小招助手；公开 Open API 开发者平台（具体产品需订阅及银行审批）。 | 可让任意个人自助授权、周期拉取所有个人账户历史交易的公开 API/MCP/CLI。 |
| 宁波银行 | 个人 App、打印交易流水、信用卡查询；公司客户银企直联和 API 服务。 | 普通消费者个人全账单的公开自助 API/MCP/CLI。 |

### 支付宝

[官方 Agent 支付用户指南](https://aipay.alipay.com/wallet-guide)（2026-11-02 检索；网站显示版本构建时间 2026-11-02）给出 `npx -y @alipay/agent-payment@latest install`，以及官方源码 [alipay/payment-skills](https://github.com/alipay/payment-skills)。仓库功能包括收银台付款、HTTP 402 付款、问题反馈、钱包开通/授权/绑定/解绑。**本次只核验，没有安装。**

[官方 Agent Pay 产品页](https://aipay.alipay.com/products/agent-pay)描述订单、用户授权、支付、凭证返回。指南中的“查看交易记录”指向支付宝 App 的账单/AI 付页面，不是一个公开批量获取消费者全部历史交易的 API。开放平台的账单下载接口则由官方商家帮助明确放在商家交易账单、资金账单、费用账单等对账范围：[支付宝商家账单获取方式](https://help.alipay.com/enterprise/knowledgeDetail.htm?knowledgeId=201603401890)。

### 微信支付

[AI 支付开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4035576716)（更新 2026-09-01）描述支付工具及插件，商户先创建 Native/JSAPI 订单，再登记 x402 支付凭据。[官方 AI 支付 FAQ](https://pay.wechatpay.cn/doc/v3/merchant/4035576771)（更新 2026-08-27）明确 AI 专属卡开通、支付确认及原有商户回调/查单。它们解决新交易支付，文档没有授予过去全部消费流水的读取权限。

[官方账单开发指引](https://pay.wechatpay.cn/doc/v3/partner/4013080593)（更新 2026-10-13）描述服务商/商户申请前三个月内某一天交易或资金账单，获得短期下载 URL。该“前三个月”和“5 分钟链接有效期”属于**商户接口**，不是消费者导出范围，也不是邮箱 ZIP 解压密码有效期。

### 招商银行

[官方小招页面](https://aixz-client-front.paas.cmbchina.com/)的可索引内容列有“流水打印”，说明可将流水证明发送邮箱；[招商银行 App 隐私政策](https://market.cmbchina.com/MPage/online/190717190011375/privacy.htm)（2026-11-02 检索）也单列小招语控和流水打印所用信息。可在用户自己的官方 App 中搜索“流水打印”或向小招提出打印指定日期范围流水的请求；最终日期、收件邮箱、验证及解压规则以官方表单为准。

[Open API 开发者服务协议 V1.1](https://openapi.cmbchina.com/serviceAgreement)明确开发者可以是单位或个人，每个 API 仍需订阅、补充协议及银行批准。因此不能笼统说“招行开放平台只允许企业”；也不能因允许个人开发者注册，就推断可以读取自己的全部借记卡/信用卡历史。[公开平台](https://openapi.cmbchina.com/)展示的主要案例包括薪福通、CBS 财资和 B2B 支付。

### 宁波银行

[官方 App 介绍](https://www.nbcb.com.cn/download_center/APP/nbbankAPP/)区分个人银行和企业银行模式；[2025-05-28 系统升级公告](https://www.nbcb.com.cn/home_page/zygg/202505/t20250528_1177903.shtml)明确 App 存在“打印交易流水”。本次没有取得当前完整逐屏导出文档，宜让用户在官方 App 搜索这一功能，不能虚构固定层级菜单。

[官方进口业务介绍](https://www.nbcb.com.cn/corporate_client/cross_border_finance/import_business/)把 API 直联说明为进口企业的系统对接，需要业务沟通、技术评估、改造、联调和上线。不能把这些企业接口称为个人开放银行授权连接。信用卡用户还有[官方查询/客服渠道](https://www.nbcb.com.cn/creditcard/client_service/service_channel/)，这与借记卡全年流水不是同一个数据集。

## 邮件导入与解压码：产品应如何表述

建议保存“该机构已用过的**账单文件解压密码**”，不要索取支付密码、登录密码、短信验证码、绑定码或人脸验证。对新到账文件先尝试已保存候选，失败后把原文件留在本地待解锁队列；允许对单个任务补充密码并继续导入。

对于已经下载、确实使用标准离线 ZIP/PDF 文件密码的文件，重新使用同一正确密码可以解开同一份未变化文件，这是本地文件格式的性质；它不是银行或支付平台承诺下次申请仍给相同密码。**下载链接过期、App 的一次性授权码、ZIP 解压密码是三件事。** 本次未从四家官方资料核实具体消费者账单密码的跨任务复用规则，因此实现必须允许更换、追加和删除候选，不应把密码永久绑定成每个来源唯一不变的秘密。

没有发现值得为此替换现有本地导入的第三方“自动拉取全历史”工具：普通 CSV/Excel 转换 CLI 只能自动化导出后的处理，无法增加官方未开放的权限；第三方包装商户 API 的 MCP 仍然只拥有商户接口范围。App 页面自动化与通知监听最多是额外选择，不是官方全历史 API，也不能保证逐条完整、跨版本稳定或免身份核验。
